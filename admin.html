① 전체 흐름 한눈에 보기

이 관리자 페이지는 index.html 파일 하나를 편집하는 도구입니다. 서버나 데이터베이스가 없어서, 아래 4단계로 동작합니다.

  1. 수정 — 아래 섹션들에서 문구·사진·링크를 고칩니다. 고친 내용은 이 브라우저 탭이 열려있는 동안 메모리에만 있고, 아직 실제 홈페이지에는 반영되지 않습니다.
  2. 미리보기 — 상단의 미리보기 버튼으로 고친 내용이 실제로 어떻게 보이는지 새 탭에서 확인합니다.
  3. 저장 — index.html 내려받기 또는 GitHub에 저장 중 하나로 수정 내용을 실제 파일에 반영합니다. (아래 ⑥·⑦번 항목에 두 방법 모두 자세히 설명돼 있습니다)
  4. 배포 반영 — GitHub Pages가 자동으로 다시 빌드되어, 1~2분 뒤 실제 홈페이지 주소에 반영됩니다. 반영 전이라면 브라우저 새로고침(Ctrl+F5)을 한 번 해보세요.

이 탭을 닫기 전에 저장하지 않은 내용이 있으면 브라우저가 "정말 나가시겠습니까?" 경고를 띄워줍니다.

② 문구(텍스트) 수정하기

홈페이지는 한국어/영어 두 언어로 되어 있어서, 대부분의 문구는 KO·EN 한 쌍으로 나타납니다.

수정 방법

  • 입력창에 바로 타이핑하면 즉시 반영됩니다 (내부적으로 값이 바뀔 뿐, 화면 자체가 바뀌는 건 아니에요 — 확인은 미리보기로).
  • 짧은 문장은 한 줄 입력창, 길거나 줄바꿈이 있는 문장은 여러 줄 입력창으로 자동으로 나뉘어 보여집니다.
  • 줄바꿈은 Enter로 입력하세요. 홈페이지에서도 그 자리에서 줄이 나뉩니다.
  • 한국어와 영어는 완전히 따로 저장됩니다. 한쪽만 고치면 다른 언어로 봤을 때는 예전 문구가 그대로 남아있으니, 내용을 바꿀 땐 KO·EN 둘 다 고쳐주세요.
  • 가격(₩150,000 – ₩200,000)처럼 언어 구분이 없는 항목은 "한국어·영어 공통" 이라고 표시되고 입력창이 하나뿐입니다 — 하나만 고치면 한국어·영어 화면 모두에 반영됩니다.
  • "소개" 섹션의 기준 인원 · 침실 · 싱글 침대는 오타 방지를 위해 셀렉트박스(숫자 선택)로, 층은 텍스트 입력으로 되어 있습니다. 이 값들도 언어 구분 없이 하나만 존재합니다.

각 입력창 위의 회색 글씨는 지금 무슨 문구를 고치는지 알려주는 미리보기 라벨입니다 (실제로 저장되는 값이 아니에요).

③ 사진 바꾸기

이 페이지에는 "사진 업로드" 버튼이 없습니다. 대신 각 사진마다 "사진 주소(경로)"를 입력하는 칸이 있고, 그 주소가 가리키는 이미지가 화면에 표시되는 방식입니다. 그래서 사진을 바꾸려면 먼저 사진 파일을 어딘가에 올려두고, 그 주소를 여기에 입력해야 합니다.

방법 A — GitHub 저장소에 올리고 경로 입력 (권장)

  1. GitHub에서 저장소 페이지로 이동합니다.
  2. assets 폴더를 열고 (없다면) photos라는 폴더를 새로 만듭니다 — Add file → Create new file에서 파일명 칸에 assets/photos/.gitkeep처럼 입력하면 폴더가 자동으로 생깁니다.
  3. assets/photos 폴더로 들어가 Add file → Upload files를 누르고 사진 파일을 끌어다 놓은 뒤 Commit changes를 누릅니다.
  4. 업로드한 파일명을 확인합니다 (예: living.jpg).
  5. 이 관리자 페이지의 사진 칸에 assets/photos/living.jpg 처럼 경로를 입력합니다. 왼쪽 미리보기 썸네일에 바로 사진이 뜨면 성공입니다.

방법 B — 이미 인터넷에 있는 사진 주소 붙여넣기

사진이 이미 어딘가(인스타그램 제외 — 외부에서 못 불러옵니다, 또는 별도 이미지 호스팅)에 올라가 있다면, 그 주소(https://...로 시작)를 그대로 붙여넣어도 됩니다.

알아두면 좋은 것

  • 사진 밑의 "사진 설명" 칸(alt 텍스트)도 함께 채워주세요 — 검색엔진 노출과 시각장애인용 스크린리더에 쓰입니다.
  • 사진 비율은 CSS가 알아서 맞춰주므로(object-fit: cover) 어떤 크기를 넣어도 레이아웃이 깨지지 않습니다. 가로 1600px 내외, 1MB 이하를 권장합니다.
  • 왼쪽 썸네일이 "미리보기 없음"으로 나오면 주소가 틀렸거나, 아직 업로드가 안 됐거나, 오탈자가 있는 경우입니다. 주소를 다시 확인해주세요.
  • 주소가 잘못되어도 실제 홈페이지가 깨지지는 않습니다 — 사진 대신 브랜드 색 그래픽이 대신 표시되도록 되어 있어요.
  • 총 15곳의 사진이 있습니다 (히어로 1 · 소개 1 · 갤러리 6 · 위치 1 · 주변 정보 5 · 예약 1). 전부 실제 사진으로 교체했다면, 갤러리 위의 "분위기 참고용 이미지" 안내 문구도 지워주세요 (해당 문구는 "공간 (갤러리)" 섹션에 있습니다).
④ 에어비앤비 예약 링크 설정

맨 위 "에어비앤비 예약 링크" 칸에 숙소의 실제 에어비앤비 주소를 넣으면, 홈페이지 안의 모든 예약 버튼(상단 메뉴, 히어로, 하단 예약 섹션, 모바일 하단 바까지)이 자동으로 그 주소로 연결됩니다.

비워두면 상단·하단 대부분의 예약 버튼은 페이지 안의 예약 섹션(#book)으로 스크롤만 하고, 맨 아래 "에어비앤비에서 예약하기" 버튼만 눌러도 반응 없는 비활성 상태로 표시됩니다.

⑤ 지도 링크 등 기타 링크

"위치" 섹션의 지도 링크 주소 칸은 "지도에서 보기" 버튼이 여는 구글 지도 주소입니다. 새 주소를 구글 지도에서 검색 → 공유 → 링크 복사로 얻어서 붙여넣으면 됩니다.

⑥ 저장하기 — 방법 A: 내려받아서 직접 올리기

아무 사전 설정 없이 바로 쓸 수 있는 방법입니다.

  1. 수정을 마쳤으면 상단의 index.html 내려받기를 누릅니다 — 컴퓨터에 index.html 파일이 다운로드됩니다.
  2. GitHub 저장소 페이지로 이동해 index.html 파일을 클릭합니다.
  3. 오른쪽 위 연필(✏) 아이콘 또는 ⋯ → Delete file 후 Add file → Upload files로 방금 받은 파일을 올립니다. (연필 아이콘으로 직접 코드를 붙여넣는 방법도 가능합니다.)
  4. 맨 아래 Commit changes를 누르면 1~2분 뒤 실제 홈페이지에 반영됩니다.

여러 명이 관리한다면, 이 방법은 매번 파일을 직접 주고받아야 해서 조금 번거로울 수 있습니다 — 자주 쓰신다면 아래 ⑦번 방법을 추천드립니다.

⑦ 저장하기 — 방법 B: GitHub에 바로 저장 (자동)

한 번만 설정해두면, 이후에는 GitHub에 저장 버튼 한 번으로 바로 반영됩니다.

1) GitHub 액세스 토큰 발급받기

  1. GitHub에 로그인한 상태에서 오른쪽 위 프로필 사진 클릭 → Settings
  2. 왼쪽 메뉴 맨 아래 Developer settings
  3. Personal access tokens → Fine-grained tokens
  4. Generate new token 클릭
  5. Token name에 알아보기 쉬운 이름 입력 (예: "연희스테이 관리자")
  6. Expiration(만료일)을 지정합니다 — 보안을 위해 반드시 설정하세요 (예: 90일).
  7. Repository access에서 Only select repositories를 고르고, 이 홈페이지 저장소 하나만 선택합니다.
  8. Permissions → Repository permissions를 펼쳐서 Contents 항목을 Read and write로 바꿉니다. (다른 권한은 건드리지 않아도 됩니다.)
  9. 맨 아래 Generate token을 누르면 github_pat_로 시작하는 토큰 문자열이 나옵니다. 이 화면을 벗어나면 다시 볼 수 없으니 바로 복사하세요.

2) 이 페이지에 등록하기

아래 "GitHub에 바로 저장" 항목에 다음을 채워주세요.

저장소계정(또는 조직)/저장소이름 형식. 예: YeonheeStay/yeonhee-stay
브랜치보통 main 그대로 두면 됩니다.
파일 경로보통 index.html 그대로 두면 됩니다.
액세스 토큰1)에서 복사한 github_pat_... 문자열

다 채우면 설정 저장을 누르세요. 상태 표시가 초록 점으로 바뀌면 준비 완료입니다. 이제부터는 수정 후 상단의 GitHub에 저장 버튼만 누르면 됩니다.

저장이 안 될 때

  • 404 / Not Found — 저장소 이름 오타, 또는 토큰이 그 저장소에 접근 권한이 없는 경우입니다. "계정/저장소이름" 형식과 대소문자를 확인하세요.
  • 401 / 403 — 토큰이 만료되었거나, Contents 권한이 Read and write가 아닌 경우입니다. 토큰을 새로 발급받아주세요.
  • 422 — 브랜치 이름이 실제와 다른 경우가 많습니다 (예: main이 아니라 master).
⑧ 보안 — 토큰 관리 시 꼭 지켜주세요

정적 웹사이트에는 진짜 로그인을 만들 수 없습니다. 서버가 없어서 비밀번호를 확인해줄 곳이 없고, 페이지 안에 비밀번호를 적어두면 소스 보기로 그대로 드러나기 때문입니다. 그래서 가짜 로그인 화면 대신 이런 방식으로 설계했습니다.

  • 이 관리자 페이지 자체에는 비밀 정보가 없습니다. 누가 이 페이지를 열더라도 내 토큰을 직접 입력하지 않는 한 홈페이지를 바꿀 수 없습니다.
  • 검색엔진에 노출되지 않도록 noindex 처리를 해두었습니다.
  • 토큰은 이 브라우저(localStorage)에만 저장되며, GitHub API 외의 다른 곳으로 전송되지 않습니다.
  • 공용 컴퓨터·공유 기기에서 사용했다면 반드시 "토큰 지우기"를 눌러주세요.
  • 가장 안전한 방법은 admin.html과 js/admin.js를 아예 GitHub에 올리지 않고, 내 컴퓨터에서 파일로 직접 열어 쓰는 것입니다 — 이 경우 처음 열 때 index.html을 선택(또는 끌어다 놓기)해야 합니다.
  • 웹에 올려서 쓰신다면 이 페이지 주소를 다른 사람과 공유하지 마시고, 토큰에는 반드시 만료일(Expiration)을 설정해주세요.
  • 토큰이 유출된 것 같다면 GitHub → Settings → Developer settings → Personal access tokens에서 즉시 Delete하면 바로 무효화됩니다.
⑨ 자주 묻는 질문
여러 명이 같이 관리해도 되나요?
네. 관리자마다 이 페이지를 각자 열고, 각자 발급받은 GitHub 토큰을 등록해서 쓰면 됩니다. 파일 자체(admin.html)는 공유해도 되지만, 토큰은 절대 다른 사람과 공유하지 마세요.
미리보기 버튼을 눌러도 새 창이 안 열려요.
브라우저의 팝업 차단 기능 때문입니다. 주소창 옆 팝업 차단 아이콘을 눌러 이 사이트의 팝업을 허용해주세요.
실수로 이상한 내용을 저장했어요. 되돌릴 수 있나요?
네. GitHub 저장소 페이지에서 index.html의 History(커밋 기록)를 열면 이전 버전을 확인하고 되돌릴 수 있습니다. 걱정된다면 중요한 수정 전에 "index.html 내려받기"로 현재 버전을 백업해두세요.
고친 내용이 홈페이지에 안 보여요.
저장(GitHub 저장 또는 파일 업로드) 후 GitHub Pages가 다시 빌드되는 데 보통 1~2분이 걸립니다. 그래도 안 보이면 브라우저 강력 새로고침(Ctrl+F5 또는 Cmd+Shift+R)을 해보세요 — 캐시 때문일 수 있습니다.
이 관리자 페이지를 컴퓨터에 저장해서 오프라인으로 써도 되나요?
네. admin.html, js/admin.js, index.html을 같은 폴더에 두고 admin.html을 더블클릭하면, 자동으로 못 읽는 대신 화면 안내에 따라 index.html을 선택(또는 끌어다 놓기)해서 쓸 수 있습니다. 이 경우 "GitHub에 저장"도 인터넷만 연결되어 있으면 그대로 동작합니다.
⑩ 공개하기 전 최종 체크리스트

GitHub에 바로 저장 (선택)

처음 한 번만 액세스 토큰을 발급받아 아래에 입력하면, 그다음부터는 상단의 GitHub에 저장 버튼 한 번으로 홈페이지에 바로 반영됩니다. 저장소 이름은 이미 채워져 있으니 액세스 토큰만 발급받아 입력하면 됩니다 (방법은 바로 아래 참고). 설정 전에 상단 버튼을 누르면 자동으로 이 화면으로 안내해드려요. 설정하지 않아도 index.html 내려받기 후 GitHub에 직접 올리는 방식으로 사용할 수 있습니다.

토큰은 이 브라우저에만 저장되며 외부로 전송되지 않습니다(GitHub 외). 공용 컴퓨터에서는 사용하지 마시고, 토큰은 이 저장소 하나에만 권한을 준 Fine-grained token으로 발급해주세요.
